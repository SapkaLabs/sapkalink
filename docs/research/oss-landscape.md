# OSS landscape for Microsoft Link to Windows interoperability

Research checkpoint: 2026-10-19 UTC. Scope: [Evaluate existing OSS for actual Microsoft-stack interoperability](https://github.com/SapkaLabs/sapkalink/issues/5). This is source research for planning; no candidate was built, installed, executed, authenticated, or tested against a phone or Microsoft service in this pass.

## Finding

**There is credible partial Microsoft-stack client groundwork: LinkMyPhone. It does not establish either fresh phone pairing or Microsoft connected-camera reception on Linux.** Its pinned source implements Microsoft account/DCG enrollment, linked-peer trust, relay transport, clipboard, and notifications. Its setup guide explicitly says that the phone must already be linked and that the client cannot pair a new phone. The strongest remaining work therefore concerns fresh linking and the actual camera control/media path, rather than proving that all Microsoft-stack communication is impossible. [LinkMyPhone setup](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/docs/getting-started/first-run.md), [bootstrap source](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/bootstrap/first_run.go), [feature catalog](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/features/catalog.go).

The target remains the existing Android **Link to Windows** stack and its actual Microsoft connected-camera input. Microsoft documents this feature under Windows 11 Mobile devices, with Android 10+, Link to Windows 1.24022.0+, linking, and a connected-camera toggle. A different companion or capture transport can inform Linux output design but does not fulfill that target. [Microsoft connected-camera documentation](https://support.microsoft.com/en-us/windows/apps/phonelink/use-your-mobile-device-s-camera).

## Direct interoperability candidates and research

### 1. YMGPwcca/linkmyphone — implemented partial Linux client

- **Pinned revision and maintenance:** [`571b8f270192ac3162f569f51fdffb1dd0d1e2d3`](https://github.com/YMGPwcca/linkmyphone/commit/571b8f270192ac3162f569f51fdffb1dd0d1e2d3), main commit dated 2026-10-07; repository not archived, API `pushed_at` 2026-10-15. Commit date and repository push time are different signals, and neither promises future support. [Repository metadata](https://api.github.com/repos/YMGPwcca/linkmyphone).
- **Actual path:** existing Link to Windows on Android, same personal Microsoft account, Linux Microsoft device-code sign-in, DCG identity/enrollment and peer trust, Microsoft Hub Relay. Original source backs the advertised implementation: enrollment is orchestrated in `bootstrap/first_run.go`; `bootstrap/trust.go` builds trust from account certificates and listed linked peers. Authentication documentation labels the Linux acquisition method an interoperability experiment and notes Windows-compatible service metadata. Service acceptance and first-party client metadata are not a public API support guarantee. [Authentication](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/docs/protocol/authentication.md), [trust source](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/bootstrap/trust.go).
- **Demonstrated feature evidence:** the maintainer reports bidirectional text/HTML/image clipboard tests and Android notification receive/actions/reply/dismissal on Samsung Galaxy S23 with CachyOS/Wayland. The validation file distinguishes live phone runs from synthetic/local tests and records network/suspend recovery tests. These are published maintainer reports, not independently reproduced results from this pass. Other phones, live token-expiry renewal, and extended operation remain unvalidated in that record. [Validation](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/docs/research/validation.md).
- **Fresh pairing gap:** new Linux PL enrollment is supported; new phone pairing is explicitly unsupported. The phone must already be linked under the account, and the guide notes an existing Windows pairing in the tested setup. Do not relabel fresh OAuth/DCG enrollment as fresh Link to Windows phone pairing. [First-run contract](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/docs/getting-started/first-run.md).
- **Camera gap:** the inspected compiled feature catalog contains clipboard and notifications only. The inspected README and validation record provide no Microsoft connected-camera receiving test. This establishes the inspected implementation boundary; it is not proof about every branch, unpublished experiment, or future version. [Catalog](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/features/catalog.go), [README](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/README.md).
- **Listed licensing and potential reuse:** [MIT](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/LICENSE); dependency notices list BSD licenses for image decoding and D-Bus. Auth/trust, framing, relay lifecycle, and test structure are promising reuse subjects. Dependency/file provenance, license obligations, and compatibility with SapkaLink's eventual license still require a scoped review before incorporation; this note grants no reuse clearance. [Third-party notices](https://github.com/YMGPwcca/linkmyphone/blob/571b8f270192ac3162f569f51fdffb1dd0d1e2d3/THIRD_PARTY_NOTICES.md).

Treat protocol details as hypotheses requiring versioned corroboration, especially where this account and LinkMyPhone use different authentication/transport paths. Listed license: [MIT](https://github.com/ZonD80/msft-phone-link-docs/blob/243a16673475aec66e93a494e8c66c89b61c4b23/LICENSE). ## Search bounds and confidence

This pass searched public GitHub repository metadata for `"phone link" linux`, `"Link to Windows"`, `"MS-CDP"`, `YPP DCG`, `"Phone Link" protocol`, and `"connected camera" microsoft`; each query requested at most 20–30 results. A broader `"Phone Link" "Linux" in:readme` returned 866 matches, of which only the first 30 were screened, so it is explicitly incomplete. Web searches used corresponding Microsoft-stack/client/camera terms. Names such as LinktoMac and other generic phone-link projects were screened through their own READMEs; branding alone was not counted as interoperability evidence.

The selected evidence set above covers six project families plus Microsoft's feature documentation. For LinkMyPhone, inspection included setup, authentication, validation, original bootstrap/trust source, and the feature catalog. For the protocol-doc repository, inspection included its README, protocol/architecture documents, and tree. For alternatives and Android adaptations, the review was documentation-level with selected protocol/license headers. This is sufficient for a planning checkpoint, not a source audit or compatibility certification.

**Bounded negative result:** this pass did not identify a public candidate with demonstrated end-to-end Linux fresh pairing plus Microsoft's connected-camera stream. That statement applies only to the selected search results and pinned material inspected here; it does not claim no compatible client exists globally. No proprietary assemblies, tokens, account payloads, credentials, captures, or private workspace reports are included in these notes.

## Planning consequences

1. Carry LinkMyPhone forward as the first reuse/provenance review candidate for DCG identity/trust, framing and relay lifecycle. Preserve its existing-linked-phone limitation in every feasibility claim.
2. Keep fresh phone linking and Microsoft camera control/media negotiation as separate unresolved investigations. Neither clipboard success nor app/screen streaming proves connected-camera reception.
3. Use KDE Connect/GSConnect for desktop interaction comparisons and scrcpy for Linux camera-output comparisons only. Their different phone/capture paths cannot satisfy the target by replacement.
4. Before any incorporation, inspect the exact files/dependencies and intended SapkaLink distribution/license. Listed upstream licenses and this technical assessment are not a verified compatibility or reuse decision.

Issue remains open for the parent planning session to reconcile these findings with the pairing and camera investigations.
